# Algorithm Study Desk

개인용 코딩테스트 학습 앱. 이 저장소는 Orca의 총괄·구현·검토 에이전트가 작은 작업을 나눠 개발하는 첫 실습이다.

## 현재 기능

문제를 제목으로 추가하고 목록에서 선택해 각 문제의 코드·자유 메모·여러 아이디어를 따로 저장·복원한다. C++ 편집기는 구문 강조·줄 번호·들여쓰기·괄호 편집·undo/redo·문자열 찾기/바꾸기를 제공한다. 코드 옆에서 아이디어 패널을 열고 닫으며 접근 방법을 모아 볼 수 있다. 처음에는 데이터분석 샘플 한 개가 보이며, 새 문제는 빈 코드·메모와 빈 아이디어 목록으로 시작한다. 문제별 AI 대화 패널에서는 Codex에 질문하고 답변을 따로 보관한다. 이번 범위는 [Issue #11](https://github.com/dheorb/algorithm-study-desk/issues/11), 이전 C++ 편집기는 [Issue #9](https://github.com/dheorb/algorithm-study-desk/issues/9), 아이디어 패널은 [Issue #7](https://github.com/dheorb/algorithm-study-desk/issues/7)에 있다.

첫 문제는 사용자의 기존 `데이터분석/sol1.cpp`를 복사해 사용한다. 원본은 수정하지 않는다. 문제 설명 원문과 프로그래머스 채점 결과는 포함하지 않는다.

## 설치와 실행

2026-11-16에 Ubuntu 26.04.1 LTS, Node **22.22.1**, npm **9.2.0**, Electron **45.3.2**, Playwright **1.65.1**에서 확인했다. Node 22.12 이상이 필요하다. 버전은 `package-lock.json`에 고정되어 있다.

```bash
npm ci
npm run build
npm start
```

Electron 바이너리는 첫 실행 때 내려받을 수 있으므로 첫 설치·실행에는 인터넷이 필요하다. `npm run build`는 esbuild로 로컬 `dist/renderer.js`와 포함 패키지의 라이선스 전문 `dist/THIRD_PARTY_NOTICES.txt`를 만든다. `npm start`와 `npm run test:e2e`도 실행 전에 자동으로 빌드하므로 산출물이 없는 checkout에서 실행할 수 있다. `dist/`는 Git에서 제외한다. 개발 서버·CDN·renderer 네트워크 요청은 없다. AI 질문을 보내면 main에서 실행한 Codex CLI가 명시한 학습 맥락을 OpenAI에 전송한다.

**현재 작업 컴퓨터의 실행 제한:** 이 Ubuntu 환경에서는 위 `npm start`가 Chromium의 `SUID sandbox helper` 오류로 종료된다. 사용자 네임스페이스도 허용되지 않아 `--disable-setuid-sandbox`만으로 해결되지 않았다. OS 설정은 변경하지 않았다. 이 컴퓨터에서 실제 실행을 확인한 로컬 개발 명령은 다음과 같다.

```bash
npm start -- --no-sandbox
```

이 옵션은 Chromium의 **OS 프로세스 샌드박스를 끈다**. 개인 로컬 개발을 위한 임시 실행 방법이며, 기본 스크립트에는 넣지 않았다. renderer의 Node 접근 차단, context isolation, 제한된 preload/IPC는 유지된다. 일상 사용·배포 전에는 시스템 관리자가 [Chromium의 Ubuntu 샌드박스 안내](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md)를 참고해 해당 실행 파일의 샌드박스를 정상 구성해야 한다. 이 환경에서 샌드박스가 켜진 실행은 확인하지 못했다.

목록에서 문제를 선택하고 **풀이 코드**와 **생각해볼점**을 편집한다. **아이디어 열기 → 아이디어 추가**를 누르면 현재 문제에 빈 아이디어를 즉시 저장하고 선택한다. 목록에서 아이디어를 골라 본문을 작성한 뒤 **저장** 또는 **Ctrl+S**를 누른다. 이 버튼은 **현재 코드·자유 메모·선택한 아이디어를 함께 저장**한다. 패널을 열 때 이미 편집 중인 코드·메모는 유지한다.

아이디어 목록 이름은 본문 첫 줄의 앞뒤 공백을 제거한 최대 60글자이며 비어 있으면 `새 아이디어`다. 같은 첫 줄과 빈 본문을 여러 개 허용한다. 목록의 번호는 읽기 편의를 위한 표시이며, 항목 구분과 저장에는 별도 UUID를 사용한다. HTML 모양 본문도 일반 텍스트다.

**새 문제 제목 → 문제 추가**는 빈 문제를 즉시 저장하고 선택한다. 목록 선택과 패널 열기만으로 파일을 쓰지는 않는다. 재실행하면 첫 문제를 선택하고 패널을 닫은 상태로 시작한다. 패널을 열면 그 문제의 첫 아이디어를 선택한다. 마지막 선택·패널 열림 상태는 저장하지 않지만, 모든 문제와 아이디어의 저장된 내용은 복원한다.

미저장 편집이 있으면 **문제/아이디어 선택·문제/아이디어 추가·패널 닫기**에서 **계속 편집 / 버리고 이동 / 저장 후 이동**을 선택한다(닫기는 `버리고 닫기 / 저장 후 닫기`). Esc도 계속 편집과 같다. 저장과 버리기 모두 **코드·자유 메모·선택 아이디어 전체**에 적용된다. 저장 실패 시 이동하거나 패널을 닫지 않고 세 초안·선택·패널을 유지한다. 버리고 추가를 선택해도 추가 자체가 실패하면 초안을 유지한다. 저장·추가 중에는 세 편집란을 읽기 전용으로 바꾸고 선택·추가·패널 전환·중복 저장을 잠근다. 요청의 문제 ID·아이디어 ID와 내용은 시작 시 고정된다. 앱 종료 시에도 미저장 편집은 **돌아가기 / 저장하지 않고 닫기**로 확인한다.

제목은 앞뒤 공백을 제거해 1~120자(HTML maxlength와 같은 UTF-16 길이)로 제한한다. 공백만 있는 값과 제어문자·줄바꿈은 거부한다. 앞뒤 공백을 제거한 **완전히 같은 제목은 중복 등록할 수 없다**. 대소문자·내부 공백은 구분한다. HTML 모양의 제목도 실행하지 않고 일반 텍스트로 표시한다.

## C++ 코드 편집

| 동작 | 방법 |
| --- | --- |
| 자동 들여쓰기·괄호 | Enter로 C++ 문맥에 맞춰 들여쓰기, `(`·`[`·`{`와 따옴표 자동 닫기, 커서 옆 대응 괄호 표시 |
| 들여쓰기/내어쓰기 | Tab / Shift+Tab, 선택한 여러 줄도 적용. 새 들여쓰기는 공백 4칸, 기존 탭은 문자 그대로 유지하고 폭 4로 표시 |
| 편집기에서 키보드로 나가기 | Esc를 누른 뒤 2초 안에 Tab. Ctrl+M으로 Tab 이동 모드를 켜고 끌 수도 있음 |
| 실행 취소/다시 실행 | Ctrl+Z / Ctrl+Shift+Z 또는 Ctrl+Y, 위쪽 한국어 버튼도 사용 가능 |
| 찾기/바꾸기 | Ctrl+F 또는 **코드 찾기·바꾸기**를 열고 문자열 입력 → 이전/다음 찾기, 한 곳/모두 바꾸기 |
| 검색창 키보드 | Enter / Shift+Enter로 다음/이전, Esc로 검색창을 닫고 코드에 포커스 복귀 |
| 저장 | Ctrl+S 또는 저장 버튼. 현재 코드·자유 메모·선택 아이디어를 함께 저장 |

찾기는 **현재 문제의 코드만** 대상으로 하고 대소문자를 구분한다. 정규식·이스케이프 해석은 하지 않으며 `.*`, `$&`도 일반 문자열이다. 빈 검색어는 작업하지 않고 안내한다. 빈 바꿀 문자열은 찾은 부분을 삭제한다. 한 곳 바꾸기는 현재 선택이 검색어와 같으면 그곳을 바꾸고, 아니면 다음 일치 항목을 찾아 바꾼다. 끝에 도달하면 처음으로 돌아간다. 바꾸기와 들여쓰기는 명령 한 번씩 undo할 수 있고, 메모·아이디어·다른 문제는 건드리지 않는다.

실제 **다른 문제로 이동하면 코드 undo/redo 이력을 초기화**한다. 같은 문제의 아이디어 선택/추가·패널 열기/닫기는 코드 값이 같으면 문서·선택·커서·이력을 유지한다. 화면 높이가 바뀌면 스크롤은 가능한 범위 안에서 조정된다. 전환 취소/Esc는 편집 위치와 이력을 유지한다. 명시적 전체 버리기로 코드가 달라지면 저장본과 빈 이력으로 돌아가 버린 코드를 undo로 복원하지 않는다. 저장은 이력을 지우지 않으며 저장 전후 입력이 한 undo 단계로 합쳐지지 않는다. 이력은 앱 재실행 후에는 복원하지 않는다.

**개행 정책:** 내부 표시 문서는 LF로 나누되 처음 읽은 원문과 첫 개행 종류를 따로 기억한다. 읽기만 하거나 코드 미편집 상태에서 메모/아이디어만 저장하면 원래 LF/CRLF·끝 개행·탭/공백을 그대로 보존한다. 코드 편집 시 처음 나타난 개행 종류(LF/CRLF/CR, 없으면 LF)로 저장하며 혼합 개행도 그 종류로 통일한다. undo로 최초 문서와 같아지면 원래 혼합 개행 문자열도 그대로 반환한다. 저장 형식은 기존 v3이며 v1/v2 이전 정책도 유지한다.

저장/추가 진행 중에는 CodeMirror의 editable·readOnly·changeFilter와 버튼 잠금을 함께 적용해 붙여넣기·잘라내기·드롭·들여쓰기·undo/redo·바꾸기를 막는다. Ctrl+S가 끝나거나 실패하면 코드에서 시작한 입력 포커스를 복원하며 실패한 편집 내용·선택·패널·이력을 유지한다.

## 문제별 Codex AI 대화

**연결 조건:** Linux의 PATH에 Codex CLI **0.169.0**이 있어야 하며 Codex 자체 로그인(`codex login status`)이 준비돼 있어야 한다. 모델은 `gpt-6.1-sol`로 고정한다. 인증정보는 앱이 읽지 않으며 별도 API 키/결제 전환은 하지 않는다. `/usr/bin/timeout`도 필요하다(이 환경은 uutils coreutils 0.10.0). CLI 없음/지원 밖 버전/설정 오류에서 기본 권한으로 재시도하지 않는다. 설치나 로그인은 사용자가 Codex의 공식 절차로 관리한다.

1. **AI 대화 열기** → 질문 입력 → **질문 보내기 / 다시 보내기**를 누른다. 기본 설명과 힌트를 요청하며 코드 제안도 텍스트로만 보여준다. 프로그램 실행이나 에디터 자동 수정은 없다.
2. 전송 순간의 **이 문제 제목·화면 코드·자유 메모·선택 아이디어 미저장 본문·나머지 저장된 아이디어**를 고정한다. 현재 문제의 최근 완료 대화 최대 **6쌍·24 KiB**를 포함하고 오래된 쌍부터 제외한다. 포함/제외 수를 각 시도에 표시한다. 다른 문제·원본 폴더·다른 앱 대화는 수집하지 않는다.
3. 질문은 **4,000 UTF-16 단위**, 질문과 현재 제목/코드/메모/아이디어 스냅샷은 합쳐 **64 KiB**까지다. 넘으면 잘라 보내지 않고 초안을 유지하며 전송을 거부한다. 전송은 학습 기록의 **저장/Ctrl+S를 대신하지 않는다**.
4. 앱 전체에 활성 요청 하나만 허용한다. 응답 중 다른 문제로 이동하거나 계속 편집해도 기존 요청은 변하지 않고 답변은 원래 문제에 붙는다. **현재 요청 취소** 뒤 늦은 답변은 무시한다. 패널 닫기와 문제 이동은 질문 초안을 유지한다.
5. 질문·답변은 같은 데이터 폴더의 **ai-chat.json**에 별도로 자동 저장한다. 응답 저장이 실패하면 질문/답변을 화면에 유지하고 **대화 저장 재시도**로 같은 ID의 저장만 반복한다. 모델을 다시 호출하지 않는다. 연결 실패/취소 뒤 **다시 보내기**는 현재 화면 맥락의 새 ID·새 시도이며 이전 실패/취소 기록은 남는다.

대화 파일은 schemaVersion 1, 문제당 200개/전체 1,000개/직렬화 8 MiB, 답변 48 KiB 제한이다. 임시 파일 동기화·원자 교체·ai-chat.json.bak 한 세대·외부 변경 감지를 적용한다. 코드/메모/아이디어의 파일과 저장 경쟁을 만들지 않으며 대화만 저장해도 기존 v1/v2/v3 학습 파일을 이전하거나 쓰지 않는다. 손상된 대화 파일은 자동 초기화하지 않고 AI만 차단한다. 원본과 .bak를 따로 보존해 복구하고 **대화 다시 불러오기**를 누른다. 기존 학습 기능은 계속 쓸 수 있다.

새 프로세스는 이전 `running` 시도를 `interrupted`로 읽어 무한 대기를 피한다. 질문 초안과 저장에 실패한 답변은 메모리에 있으므로 종료 전에 보관해야 한다. 앱 종료에는 보호 안내가 나오며 취소하면 계속 편집한다. 정상 답변 저장 후 원래 질문과 같은 초안만 비우고, 응답 대기 중 새로 쓴 질문은 남긴다. CLI 자식은 취소/정상 종료 시 프로세스 그룹을 종료하며, 앱이 강제 종료돼도 별도 timeout 프로세스가 60초 제한(추가 강제 종료 유예 1초)을 유지한다. 강제 종료로 남은 앱 소유 /tmp 작업 폴더는 자동 복구하지 않는다.

**도구 제한:** `exec --json --ephemeral --ignore-user-config --ignore-rules --strict-config`와 실행별 명명 권한 `study-deny`(`filesystem={"/"="deny"}`, `network={enabled=false}`)를 사용한다. `--sandbox read-only`와 혼용하지 않는다. shell/이미지/앱/MCP/플러그인/브라우저·검색/스킬/메모리/하위 에이전트와 자동 맥락은 개별 제한한다. `functions.exec/wait` 이름과 숨은 patch handler는 남으므로 **도구 0개나 모든 OS의 완전 격리를 주장하지 않는다**. 이 버전·구성의 합성 경계 시험과 제한, 과거 read-only 후보의 실패는 [보고서](docs/tasks/011-ai-chat-report.md)에 기록한다. Codex 자체 인증·모델 통신·앱 소유 임시 로그/상태 생성은 이 도구 권한과 별개다.

```bash
# 실제 모델을 부르지 않는 합성 도구/맥락/설정 실패 검증
node scripts/verify-codex-boundary.cjs
# 과거 실패 구성의 비교 재현: 읽기가 관찰되므로 종료 1이 예상됨
node scripts/verify-codex-boundary.cjs --legacy-read-only
```

네트워크/사용량/로그인 오류는 비밀이나 원시 stderr를 노출하지 않는 한국어 안내로 표시한다. 질문의 전송 범위는 패널에서 확인할 수 있다. 문제 원문·제약·채점 결과가 없으므로 AI 답변은 정답 판정이 아니다.

## 기록 보관과 실패 처리

- 기본 기록: Electron `appData` 아래 고정 폴더 `algorithm-study-desk/study-record.json`. 일반 Linux에서는 `~/.config/algorithm-study-desk/study-record.json`이며 `XDG_CONFIG_HOME` 설정에 따라 달라질 수 있다. 화면의 **기록 보관 위치**에서 실제 경로를 확인한다.
- 앱 버전이나 worktree 이름을 경로에 포함하지 않는다. 여러 작업공간에서 실행해도 같은 사용자 기록을 읽고, 같은 데이터 폴더를 사용하는 앱은 하나만 실행한다.
- 파일은 아래 v3 구조의 문제 목록이다. 기존 데이터분석 ID는 `data-analysis`, 새 문제와 아이디어는 main에서 만든 UUID v4를 쓴다. 제목·첫 줄·목록 위치를 저장 대상으로 사용하지 않는다. 아이디어 ID는 파일 전체에서 유일하며 저장 시 해당 문제 소속인지도 검증한다. 빈 코드·메모·아이디어 본문도 유효하다.
- 문제 최대 1,000개, 문제별 아이디어 최대 100개, 코드 1,048,576 / 메모·아이디어 본문 각각 262,144 UTF-16 단위, 직렬화한 전체 파일 8 MiB 제한을 읽기·쓰기 양쪽에 적용한다.
- 문제의 `savedAt`은 코드·메모 저장 시각, 아이디어의 `savedAt`은 본문 저장 시각이다. 새 빈 항목은 `null`이다. 아이디어 추가·본문만 변경하면 기존 코드·메모 시각(`null` 포함)을 유지한다. 코드·메모가 바뀌거나 아이디어 선택 없이 미저장 문제를 처음 저장하면 문제 시각을 갱신한다. 아이디어 본문이 바뀌거나 처음 저장되면 아이디어 시각을 갱신한다. 다른 문제·아이디어의 값과 시각은 유지한다.
- 같은 폴더에 권한 `0600`인 임시 파일을 만들고 내용을 동기화한 후 원자적으로 교체한다. 교체 전 정상 기록은 `study-record.json.bak`에 한 세대 보관한다. 저장 성공은 파일과 디렉터리 동기화가 끝난 뒤에만 표시한다.
- 권한·용량·쓰기 오류 시 성공으로 표시하지 않고 편집 내용과 재시도 버튼을 유지한다. 파일 교체 후 동기화가 실패하면 디스크에 새 내용이 있을 수 있으므로 **확인 실패**로 표시한다. 이때 추가된 문제는 목록에 표시하되 현재 선택을 유지하며, 안내에 따라 해당 항목을 선택해 저장을 재시도한다. 같은 제목 재등록으로 항목을 중복 생성하지 않는다.
- 아이디어 추가 후 동기화가 실패하면 새 아이디어를 목록에 보이면서 현재 초안을 유지하고 **추가 확인 재시도**를 표시한다. 재시도는 반환받은 같은 ID를 사용한다. `저장 후 이동`에서 전체 저장은 성공하고 이어진 재확인이 다시 실패해도, 진행 중이던 원래 ID를 유지해 다음 재시도가 빈 항목을 중복 생성하지 않게 한다. 재확인 작업과 별도로 저장을 완료하거나 앱을 다시 시작하면 일반 추가로 돌아간다. 그 이후 명시적인 추가는 별개의 빈 아이디어를 만든다.
- 손상된 JSON, 지원하지 않는 스키마, 잘못된 필드, 너무 큰 파일은 저장을 차단한다. 앱을 연 뒤 외부에서 기록이 변경·삭제된 경우도 덮어쓰지 않는다.
- 손상 파일을 자동으로 초기화하거나 백업으로 자동 복구하지 않는다. 앱을 닫고 원본, `.bak`, `study-record.v1.json`, `study-record.v2.json`을 **다른 이름으로 복사해 보존**한 후 내용을 확인한다. 복구할 정상 백업을 선택해 `study-record.json`으로 복사하고 앱을 다시 연다. 저장 오류 화면에 편집 내용이 있다면 먼저 별도로 복사해 둔다.

```json
{
  "schemaVersion": 3,
  "problems": [
    {
      "id": "data-analysis",
      "title": "데이터분석",
      "code": "// 저장한 코드",
      "notes": "생각해볼점",
      "savedAt": "2026-11-16T02:00:00.000Z",
      "ideas": [
        {
          "id": "ff08497a-3769-42b0-a5bb-5f224238c12e",
          "body": "정렬을 먼저 해 보면 어떨까?\n시간 복잡도를 비교해 보자.",
          "savedAt": "2026-11-16T03:00:00.000Z"
        }
      ]
    }
  ]
}
```

### 기존 v1/v2 기록의 이전

앱 시작 시 `schemaVersion: 1`은 목록 한 항목으로, v2 목록은 각 문제에 빈 `ideas` 배열을 붙여 **메모리에서만** v3로 해석한다. 기존 문제 ID·제목(v1은 고정 데이터분석)·코드·메모·저장 시각을 유지한다. 빈 값과 `null` 시각을 샘플로 대체하지 않으며 읽기만으로 파일을 쓰지 않는다. 첫 **저장·문제 추가·아이디어 추가** 때 v3로 옮긴다. 값이 변경되지 않은 기존 시각은 위 저장 규칙에 따라 보존한다.

교체 전에 원래 바이트(공백·개행 포함)를 v1이면 `study-record.v1.json`, v2이면 `study-record.v2.json`에 권한 `0600`으로 보존하고 동기화한다. 두 사본은 서로와 `.bak`에 독립적이며 후속 저장으로 교체하지 않는다. 이미 같은 바이트의 사본이 있으면 재사용하고, 다른 사본이면 덮어쓰지 않고 이전을 중단한다. 이전 사이클의 v1 사본이 있는 v2 기록도 두 사본을 각각 보존한다. 사본을 완성하기 전에 원본을 교체하지 않으며, 사본 생성 이후 이전 실패도 원본에서 재실행·재시도할 수 있다.

복구가 필요하면 현재 파일과 모든 사본을 별도로 보존한 뒤 앱을 닫고 정상 사본을 `study-record.json`으로 복사한다. 예전 사본에는 **이전 이후 추가·수정한 문제나 아이디어가 없으므로** 현재 v3 파일도 반드시 보존한다. 손상·미지원 버전이나 잘못된 ID·필드는 자동 복구·초기화하지 않는다. v3를 지원하지 않는 예전 앱으로 파일을 열어 편집하지 않는다.

일반 로컬 파일시스템을 대상으로 한다. 저장 도중 외부 프로그램이 같은 파일을 고치는 경쟁, 실제 전원 차단·하드웨어 고장까지 보장하지 않는다. `.bak`은 전체 변경 이력이 아니다. 비정상 종료로 남은 `.tmp` 파일을 자동 복원하거나 삭제하지 않는다.

7. 실제 키보드로 Enter·Tab/Shift+Tab·괄호·undo/redo·포커스 탈출을 확인하고 키워드 색/줄 번호/대응 괄호도 검사한다. 찾기 다음/이전·특수문자 문자열·한 곳/모두/빈 값 바꾸기·undo·코드 외 영역 분리를 확인한다.
8. 취소 후 커서·선택·스크롤·이력, 같은 문제의 패널/목록 상호작용, A/B 이력 초기화, 저장 후 dirty/undo·실패 후 위치/이력·재시도, v1/v2/v3 CRLF와 혼합 개행·끝 개행·탭/공백·빈 코드·새 PID를 검사한다. Unicode 입력은 자동 붙여넣기/키 입력이며 직접 한글 IME 검증은 아니다.

통합 검증은 매번 `/tmp/study-desk-e2e-*`를 만들고 끝나면 제거한다. 사용자 기록을 읽거나 수정하지 않는다. 화면 캡처는 `test-results/`에 남는다. 이번에는 패널 열림/닫힘, 세 초안의 미저장 선택창, 권한 실패, 동기화 실패 후 추가 재시도, 740px 좁은 창을 직접 열어 확인했다. 테스트 결과와 캡처는 Git에서 제외한다.

수동 확인도 사용자 기록과 분리할 수 있다. 같은 임시 경로를 다시 사용해야 재시작 복원을 확인할 수 있다.

```bash
STUDY_DESK_TEST_DIR=$(mktemp -d /tmp/study-desk-manual-XXXXXX)
STUDY_DESK_DATA_DIR="$STUDY_DESK_TEST_DIR" npm start -- --no-sandbox
# 앱에서 저장 후 종료하고, 같은 셸에서 다시 실행
STUDY_DESK_DATA_DIR="$STUDY_DESK_TEST_DIR" npm start -- --no-sandbox
```

샌드박스가 정상 구성된 시스템에서는 `--no-sandbox`를 빼고 실행한다. `STUDY_DESK_DATA_DIR`는 저장소 밖의 절대 경로여야 한다. 이 환경변수를 사용하면 기록뿐 아니라 Electron의 사용자 데이터·캐시·실행 잠금도 분리된다.

## 구성과 참고 문서

- `src/main.cjs`: 창, 데이터 경로, 단일 실행 잠금, IPC 발신자 검증. 외부 탐색·새 창·권한 요청 차단.
- `src/preload.cjs`: 고정된 학습 API `load()`, `save({id, code, notes, idea: null | {id, body}})`, `create(title)`, `createIdea(problemId, retryIdeaId?)`를 공개한다. 대화는 별도 `studyChat`의 `load/send/cancel/retrySave/onState`로만 접근한다. 임의 실행 파일·명령·파일 경로·IPC 채널을 받지 않는다.
- `src/store.cjs`: v1/v2/v3 검사·이전, ID 기반 코드·메모·선택 아이디어의 원자적 저장, 복구 사본·백업·외부 변경 감지. renderer에는 파일시스템이나 프로세스 API를 노출하지 않는다.
- `src/renderer.js`, `src/index.html`, `src/styles.css`: 한국어 편집 화면, 저장·오류·미저장 상태. 외부 스크립트·폰트·네트워크 요청 없음.
- `src/code-editor.js`: CodeMirror 조합·문서/개행·이력·명령/검색 UI·잠금 어댑터. 테스트는 실제 키보드/클립보드로 편집하며 전체 문서 단언은 가상 스크롤 밖 내용까지 읽는다.
- `scripts/build.cjs`: 로컬 browser 번들과 라이선스 전문 생성. CSP는 `script-src 'self'`를 유지하고 CodeMirror가 만드는 스타일 태그의 nonce만 `style-src`에 허용한다. `unsafe-inline`/`unsafe-eval`은 허용하지 않는다.

CodeMirror 직접 의존성은 state **6.7.6**, view **6.43.15**, commands **6.11.1**, language **6.13.1**, lang-cpp **6.0.3**, search **6.7.2**, autocomplete **6.20.4**다. autocomplete는 괄호 자동 닫기만 사용하며 자동완성 UI는 켜지 않는다. 빌드용 esbuild는 **0.28.2**다. 모두 MIT이며 실제 번들에 포함되는 전이 패키지의 라이선스도 생성 파일에 모은다. 정확한 직접 버전과 전이 버전/무결성은 lockfile로 고정한다.

확인한 편집기 공식 자료: [C++ 확장과 소스 이전 안내](https://github.com/codemirror/lang-cpp), [이전된 공식 저장소](https://code.haverbeke.berlin/codemirror/lang-cpp), [CodeMirror API](https://codemirror.net/docs/ref/), [Tab 접근성 안내](https://codemirror.net/examples/tab/), [esbuild API](https://esbuild.github.io/api/). CodeMirror 문서 사이트 조회는 403이어서 설치된 공식 패키지의 README·dist/index.d.ts·배포 소스에서 API·개행·잠금·CSP nonce 동작도 확인했다.

구현 시 확인한 공식 문서: [Electron 보안](https://www.electronjs.org/docs/latest/tutorial/security), [preload와 IPC](https://www.electronjs.org/docs/latest/tutorial/ipc), [앱 데이터 경로와 실행 잠금](https://www.electronjs.org/docs/latest/api/app), [Node 파일시스템](https://nodejs.org/api/fs.html), [Playwright Electron](https://playwright.dev/docs/api/class-electron), [Ubuntu AppArmor](https://documentation.ubuntu.com/security/security-features/privilege-restriction/apparmor/).
