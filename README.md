# Algorithm Study Desk

개인용 코딩테스트 학습 앱. 이 저장소는 Orca의 총괄·구현·검토 에이전트가 작은 작업을 나눠 개발하는 첫 실습이다.

## 현재 기능

문제를 제목으로 추가하고 목록에서 선택해 각 문제의 코드·메모를 따로 저장·복원한다. 처음에는 데이터분석 샘플 한 개가 보이며, 새 문제는 빈 코드와 메모로 시작한다. 상세 범위는 [Issue #5](https://github.com/dheorb/algorithm-study-desk/issues/5)에 있다.

첫 문제는 사용자의 기존 `데이터분석/sol1.cpp`를 복사해 사용한다. 원본은 수정하지 않는다. 문제 설명 원문과 프로그래머스 채점 결과는 포함하지 않는다.

## 역할

- 총괄: 프로젝트 `main`의 총괄 대화. 작업 정의, 구현·검토 담당 배정, 결과 취합.
- 구현: 첫 기능 구현과 검증, 실행 방법 작성.
- 검토: 요구사항과 실제 동작을 독립적으로 확인하고 수정 필요 사항 보고.

상세 요구사항: [첫 작업](docs/tasks/001-study-record.md)

사용자는 총괄에게 대화로 요청한다. 총괄은 Issue를 작성하고 담당자에게 링크를 전달하며, 구현·검토 담당은 같은 Issue를 기준으로 작업한다. 총괄이 결과를 확인해 PR을 병합한다. 첫 기능은 GitHub 연결 전에 로컬에서 검토·병합했으며 기존 커밋 이력을 그대로 보존했다.

## 설치와 실행

2026-11-16에 Ubuntu 26.04.1 LTS, Node **22.22.1**, npm **9.2.0**, Electron **45.3.2**, Playwright **1.65.1**에서 확인했다. Node 22.12 이상이 필요하다. 버전은 `package-lock.json`에 고정되어 있다.

```bash
npm ci
npm start
```

Electron 바이너리는 첫 실행 때 내려받을 수 있으므로 첫 설치·실행에는 인터넷이 필요하다. 앱에는 별도 빌드나 서버가 없고, 실행 후에는 네트워크 없이 동작한다.

**현재 작업 컴퓨터의 실행 제한:** 이 Ubuntu 환경에서는 위 `npm start`가 Chromium의 `SUID sandbox helper` 오류로 종료된다. 사용자 네임스페이스도 허용되지 않아 `--disable-setuid-sandbox`만으로 해결되지 않았다. OS 설정은 변경하지 않았다. 이 컴퓨터에서 실제 실행을 확인한 로컬 개발 명령은 다음과 같다.

```bash
npm start -- --no-sandbox
```

이 옵션은 Chromium의 **OS 프로세스 샌드박스를 끈다**. 개인 로컬 개발을 위한 임시 실행 방법이며, 기본 스크립트에는 넣지 않았다. renderer의 Node 접근 차단, context isolation, 제한된 preload/IPC는 유지된다. 일상 사용·배포 전에는 시스템 관리자가 [Chromium의 Ubuntu 샌드박스 안내](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md)를 참고해 해당 실행 파일의 샌드박스를 정상 구성해야 한다. 이 환경에서 샌드박스가 켜진 실행은 확인하지 못했다.

목록에서 문제를 선택하고 **풀이 코드**와 **생각해볼점**을 편집한 뒤 **저장** 또는 **Ctrl+S**를 누른다. **새 문제 제목 → 문제 추가**는 빈 항목을 즉시 파일에 저장하고 선택한다. 목록 선택만으로 파일을 쓰지는 않으며 재실행하면 첫 항목을 선택한다. 목록과 각 문제의 저장된 내용은 모두 복원된다.

미저장 편집이 있는 상태에서 선택·추가를 시도하면 **계속 편집 / 버리고 이동 / 저장 후 이동**을 선택한다. Esc도 계속 편집과 같다. 저장 실패 시 이동하지 않고 현재 편집과 선택을 유지한다. 버리고 새 문제로 이동을 선택해도 추가 자체가 실패하면 기존 초안을 유지한다. 저장·추가 요청 중에는 편집을 잠시 읽기 전용으로 바꾸고 선택·추가·중복 저장을 막는다. 저장 요청의 문제 ID와 내용은 요청 시작 시 고정되며, 완료 후 다시 편집할 수 있다. 앱 종료의 미저장 확인도 유지한다.

제목은 앞뒤 공백을 제거해 1~120자(HTML maxlength와 같은 UTF-16 길이)로 제한한다. 공백만 있는 값과 제어문자·줄바꿈은 거부한다. 앞뒤 공백을 제거한 **완전히 같은 제목은 중복 등록할 수 없다**. 대소문자·내부 공백은 구분한다. HTML 모양의 제목도 실행하지 않고 일반 텍스트로 표시한다.

## 기록 보관과 실패 처리

- 기본 기록: Electron `appData` 아래 고정 폴더 `algorithm-study-desk/study-record.json`. 일반 Linux에서는 `~/.config/algorithm-study-desk/study-record.json`이며 `XDG_CONFIG_HOME` 설정에 따라 달라질 수 있다. 화면의 **기록 보관 위치**에서 실제 경로를 확인한다.
- 앱 버전이나 worktree 이름을 경로에 포함하지 않는다. 여러 작업공간에서 실행해도 같은 사용자 기록을 읽고, 같은 데이터 폴더를 사용하는 앱은 하나만 실행한다.
- 파일은 아래 v2 구조의 문제 목록이다. 기존 데이터분석 ID는 `data-analysis`, 새 문제는 main에서 만든 UUID v4를 쓴다. 제목·목록 위치를 저장 대상으로 사용하지 않는다. 빈 코드·빈 메모도 유효하다. 새 빈 항목의 `savedAt`은 `null`이며 풀이를 저장하면 ISO 시각으로 바뀐다.
- 문제 최대 1,000개, 코드 1,048,576 / 메모 262,144 UTF-16 단위, 직렬화한 전체 파일 8 MiB 제한을 읽기·쓰기 양쪽에 적용한다. 다른 문제를 저장하거나 추가해도 기존 항목의 코드·메모·저장 시각은 그대로 유지된다.
- 같은 폴더에 권한 `0600`인 임시 파일을 만들고 내용을 동기화한 후 원자적으로 교체한다. 교체 전 정상 기록은 `study-record.json.bak`에 한 세대 보관한다. 저장 성공은 파일과 디렉터리 동기화가 끝난 뒤에만 표시한다.
- 권한·용량·쓰기 오류 시 성공으로 표시하지 않고 편집 내용과 재시도 버튼을 유지한다. 파일 교체 후 동기화가 실패하면 디스크에 새 내용이 있을 수 있으므로 **확인 실패**로 표시한다. 이때 추가된 문제는 목록에 표시하되 현재 선택을 유지하며, 안내에 따라 해당 항목을 선택해 저장을 재시도한다. 같은 제목 재등록으로 항목을 중복 생성하지 않는다.
- 손상된 JSON, 지원하지 않는 스키마, 잘못된 필드, 너무 큰 파일은 저장을 차단한다. 앱을 연 뒤 외부에서 기록이 변경·삭제된 경우도 덮어쓰지 않는다.
- 손상 파일을 자동으로 초기화하거나 백업으로 자동 복구하지 않는다. 앱을 닫고 원본, `.bak`, `study-record.v1.json`을 **다른 이름으로 복사해 보존**한 후 내용을 확인한다. 복구할 정상 백업을 선택해 `study-record.json`으로 복사하고 앱을 다시 연다. 저장 오류 화면에 편집 내용이 있다면 먼저 별도로 복사해 둔다.

```json
{
  "schemaVersion": 2,
  "problems": [
    {
      "id": "data-analysis",
      "title": "데이터분석",
      "code": "// 저장한 코드",
      "notes": "생각해볼점",
      "savedAt": "2026-11-16T02:00:00.000Z"
    }
  ]
}
```

### 기존 v1 기록의 이전

앱 시작 시 `schemaVersion: 1`을 읽으면 메모리에서만 목록 한 항목으로 해석한다. 기존 코드·메모(빈 값 포함)·저장 시각은 변환하거나 샘플로 대체하지 않으며 파일을 쓰지 않는다. 첫 **저장 또는 문제 추가** 때 v2로 옮긴다. 문제 추가는 기존 항목의 저장 시각을 유지하고, 기존 항목의 풀이를 직접 저장한 경우만 그 항목의 저장 시각을 갱신한다.

교체 전에 v1 원래 바이트(공백·개행 포함)를 `study-record.v1.json`에 권한 `0600`으로 보존하고 동기화한다. 이 사본은 `.bak`과 별개이며 후속 저장으로 교체하지 않는다. 이미 같은 바이트의 사본이 있으면 재사용하고, 다른 사본이면 덮어쓰지 않고 이전을 중단한다. 사본을 완성하기 전에 원본을 교체하지 않으며, 사본 생성 이후 이전 실패도 원본에서 재실행·재시도할 수 있다.

복구가 필요하면 현재 파일과 모든 사본을 별도로 보존한 뒤 앱을 닫고 정상 사본을 `study-record.json`으로 복사한다. v1 사본으로 복구하면 **이전 이후 추가한 문제는 그 사본에 없으므로** 현재 v2 파일도 반드시 보존한다. 손상·미지원 버전이나 잘못된 ID·필드는 자동 복구·초기화하지 않는다.

일반 로컬 파일시스템을 대상으로 한다. 저장 도중 외부 프로그램이 같은 파일을 고치는 경쟁, 실제 전원 차단·하드웨어 고장까지 보장하지 않는다. `.bak`은 전체 변경 이력이 아니다. 비정상 종료로 남은 `.tmp` 파일을 자동 복원하거나 삭제하지 않는다.

## 검증

```bash
npm test
xvfb-run -a npm run test:e2e
```

Issue #5에서 저장 계층 **12개**, Electron 통합 **9개**가 통과했다(건너뜀 없음). GUI가 있는 환경에서는 `npm run test:e2e`로도 실행할 수 있다. `xvfb-run`이 없는 환경은 별도로 Xvfb를 설치해야 한다. Playwright는 설치된 Electron을 사용하므로 별도의 Playwright 브라우저 설치는 필요 없다.

통합 테스트는 Linux에서 Playwright의 기본 설정인 OS 샌드박스 비활성 상태로 실행한다. 샌드박스를 구성한 시스템에서는 `STUDY_DESK_TEST_SANDBOX=1 xvfb-run -a npm run test:e2e`로 활성화할 수 있지만, 이 명령은 현재 컴퓨터에서 통과를 확인하지 않았다.

검증 내용:

1. 실제 UI 추가·빈 항목·A/B 반복 선택·독립 저장. 한국어·이모지와 빈 값을 파일과 입력란에서 비교하고, SIGKILL 후 새 PID와 정상 종료 후 재실행에서 모두 복원한다.
2. 선택·추가 각각의 계속 편집/Esc·버리기·저장 후 이동. 실제 `chmod 500` 권한 오류에서 현재 선택·초안·파일 보존 및 권한 복구 후 재시도를 확인한다. root에서는 권한 검증을 건너뛰므로 일반 사용자로 실행한다.
3. 저장 계층의 실제 파일 작성 직전에 테스트만 지연을 주어 추가 입력·전환·추가·반복 Ctrl+S를 시도한다. 편집의 읽기 전용 상태와 시작 시점의 ID/스냅샷 저장을 확인한다. 제품에 테스트용 IPC나 지연 옵션은 추가하지 않았다.
4. 직접 만든 v1 fixture의 원래 바이트와 내용·시각 보존, 첫 이전, v2 새 PID 복원, 후속 저장 뒤에도 복구 사본이 유지되는지 확인한다. 저장 계층에서 백업 작성·원본 교체 실패를 주입하고 재실행·재시도한다.
5. 손상·미지원 버전·잘못된 구조/ID/필드·외부 변경/삭제·입력 및 전체 파일 크기 제한·복구 사본 충돌을 검사한다. 교체 후 동기화 오류는 테스트에서 주입해 실패로 표시하고 새 항목을 중복 생성하지 않는지 확인한다.
6. renderer의 `require`·`process` 차단과 `load`·`save`·`create`만 노출되는지 확인한다. HTML 모양 제목은 텍스트로 표시하며, 740px 좁은 창에서 가로 넘침이 없다. 종료 확인 대화상자는 반환값을 '돌아가기'로 대체해 초안 보존을 확인한다.

통합 검증은 매번 `/tmp/study-desk-e2e-*`를 만들고 끝나면 제거한다. 사용자 기록을 건드리지 않는다. 화면 캡처는 `test-results/`에 남으며 목록 복원, 미저장 선택창, 권한 실패, 저장 중, 이전 후, 손상 파일, 좁은 창 화면을 직접 확인했다. 테스트 결과와 캡처는 Git에서 제외한다.

수동 확인도 사용자 기록과 분리할 수 있다. 같은 임시 경로를 다시 사용해야 재시작 복원을 확인할 수 있다.

```bash
STUDY_DESK_TEST_DIR=$(mktemp -d /tmp/study-desk-manual-XXXXXX)
STUDY_DESK_DATA_DIR="$STUDY_DESK_TEST_DIR" npm start -- --no-sandbox
# 앱에서 저장 후 종료하고, 같은 셸에서 다시 실행
STUDY_DESK_DATA_DIR="$STUDY_DESK_TEST_DIR" npm start -- --no-sandbox
```

샌드박스가 정상 구성된 시스템에서는 `--no-sandbox`를 빼고 실행한다. `STUDY_DESK_DATA_DIR`는 저장소 밖의 절대 경로여야 한다. 이 환경변수를 사용하면 기록뿐 아니라 Electron의 사용자 데이터·캐시·실행 잠금도 분리된다.

## 구성과 참고 문서

- `src/main.cjs`: 창, 데이터 경로, 단일 실행 잠금, IPC 발신자 검증. 외부 탐색·새 창·권한 요청 차단.
- `src/preload.cjs`: 고정된 `load()`, `save({id, code, notes})`, `create(title)` API만 공개. 임의 파일 경로나 IPC 채널을 받지 않는다.
- `src/store.cjs`: v1/v2 검사·이전, ID 기반 단일 항목 변경, 백업·원자적 저장·외부 변경 감지. renderer에는 파일시스템이나 프로세스 API를 노출하지 않는다.
- `src/renderer.js`, `src/index.html`, `src/styles.css`: 한국어 편집 화면, 저장·오류·미저장 상태. 외부 스크립트·폰트·네트워크 요청 없음.

구현 시 확인한 공식 문서: [Electron 보안](https://www.electronjs.org/docs/latest/tutorial/security), [preload와 IPC](https://www.electronjs.org/docs/latest/tutorial/ipc), [앱 데이터 경로와 실행 잠금](https://www.electronjs.org/docs/latest/api/app), [Node 파일시스템](https://nodejs.org/api/fs.html), [Playwright Electron](https://playwright.dev/docs/api/class-electron), [Ubuntu AppArmor](https://documentation.ubuntu.com/security/security-features/privilege-restriction/apparmor/).

C++ 실행·채점, AI 대화, 추천, 외부 제출, 검색·삭제·이름 변경·일괄 가져오기는 이번 범위에 포함하지 않는다. 샘플 알고리즘의 정답 여부는 검증하지 않았다. OS sandbox 활성 실행, 직접 한글 IME 입력, OS 네이티브 종료 대화상자의 수동 클릭, 실제 전원 차단은 검증하지 않았다.
