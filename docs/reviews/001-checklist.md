# 001 검토 준비: 코드·메모 저장과 복원

상태: **검토 기준 작성 완료 / 구현 검증 미실행**. 이 문서는 구현 완료 후 독립 검토에 사용할 절차이며, 통과를 뜻하지 않는다.

근거: [작업 규칙](../../AGENTS.md), [기능 요구사항](../tasks/001-study-record.md), [지정 샘플](../../samples/data-analysis.cpp).
대상은 고정된 데이터분석 문제 하나의 한국어 UI, 코드·메모 편집, 로컬 저장과 재실행 복원이다. 샘플의 알고리즘 정답 여부·컴파일·제출은 검토 범위에 포함하지 않는다.

## 시작 전 받을 정보

- 구현 작업공간·브랜치·커밋, 변경 파일 목록, 구현 담당 결과 보고와 알려진 제한.
- README의 설치·실행·검증 명령, 필요한 런타임과 Linux 화면 실행환경.
- 실제 저장 경로·파일 형식, 앱 사용자 데이터 경로 결정 방식, 테스트용 데이터 디렉터리를 지정하는 방법.
- 저장 실패 및 손상 파일 재현 방법과 기존 자동 검증 명령·결과.

실제 검토에서는 위 커밋을 대상으로 실행한다. 기록이 없는 임시 사용자 데이터 디렉터리를 쓰고, 실패·손상 실험은 그 안의 시험 기록에만 수행한다. 실제 사용자 기록과 원본 학습 폴더의 파일·권한은 건드리지 않는다. 테스트 경로를 안전하게 분리할 수 없으면 해당 확인을 보류하고 사유를 보고한다.

## 수동 확인

각 행을 실행한 뒤에만 `통과 / 실패 / 미확인`과 증거를 기록한다. 현재 모든 항목은 **미실행**이다.

| 항목 | 확인 절차 | 통과 기준 |
| --- | --- | --- |
| M1 실제 UI 실행 | README대로 설치·실행하고 실제 Linux 데스크톱 앱 창을 확인한다. 기록이 없는 상태에서 문제 제목, 코드·메모 편집 영역, 저장 버튼·상태를 보고 두 영역에 입력한다. | 한국어 UI가 보이고 조작되며 초기 코드는 지정 샘플과 일치한다. 빌드 성공이나 프로세스 실행 로그만으로 UI 통과를 판정하지 않는다. |
| M2 정상 저장 | 코드 끝에 `// 검토 저장 A`를 붙이고 메모에 `생각해볼점 A`와 줄바꿈을 입력한 뒤 저장한다. 실제 기록 파일의 두 값을 확인한다. 두 값을 B로 바꿔 다시 저장한다. | 저장 성공 표시와 디스크의 코드·메모가 일치한다. 한글·줄바꿈이 유지되고 두 번째 저장도 반영된다. 저장 파일은 저장소와 원본 학습 폴더 밖의 앱 사용자 데이터 디렉터리에 있다. |
| M3 종료·재실행 복원 | M2 저장 후 앱을 완전히 종료하고 관련 앱 프로세스가 끝났음을 확인한다. 같은 사용자 데이터 경로로 명령을 새로 실행하고 두 편집 영역을 비교한다. | 코드와 메모가 모두 마지막 저장값 B로 정확히 복원된다. 화면 새로고침이나 개발 서버의 자동 재로딩을 재실행 증거로 쓰지 않는다. |
| M4 저장 실패와 재시도 | B가 저장된 상태에서 코드·메모를 C로 편집한다. 일반 사용자로 임시 저장 디렉터리의 쓰기를 막거나 구현자가 제공한 실패 주입 방법으로 실제 저장 실패를 일으킨다. 저장 후 화면과 기존 파일을 확인하고, 실패 조건을 해제하여 다시 저장·재실행한다. | 오류가 보이고 성공으로 표시되지 않는다. 화면의 코드·메모 C가 모두 남아 있고 기존 저장값 B도 훼손되지 않는다. 재시도 후 C가 저장·복원된다. 파일 하나의 권한 변경만으로 실패를 가정하지 않고 실제 오류 발생을 확인한다. |

| M6 작업공간·버전 변경 | 저장 경로 결정 코드를 읽어 작업공간 경로나 앱 버전에 의존하는지 확인한다. 제공된 다른 작업공간이나 다른 버전 빌드가 있으면 같은 사용자 데이터로 순차 실행해 B 또는 C 기록을 비교한다. | 같은 앱의 기록을 계속 읽고 시작 시 샘플로 덮어쓰지 않는다. 실행 비교를 못 했다면 코드 확인과 미실행 부분을 구분한다. 검토자가 버전 변경을 위해 제품 코드를 수정하지 않는다. |
| M7 원본 보존·문서 | 변경 목록과 파일 쓰기 경로를 확인한다. 지정 원본 `데이터분석/sol1.cpp`의 실행 전후 해시를 비교하고, 구현 전 기준 해시가 있으면 함께 비교한다. README 명령과 실제 실행 결과를 대조한다. | `/home/dheorb/workspace/study/algorithms`를 쓰기 대상으로 삼지 않고 원본을 수정·이동·삭제하지 않는다. 해시 비교가 증명하는 파일·기간만 보고하며 기준이 없으면 구현 이전 보존은 미확인으로 남긴다. README에 확인된 실행·검증 방법과 제한이 있다. |

원본 확인은 지정 코드와 필요한 경로 정보만 읽는다. 계정 정보·인증 파일·토큰을 탐색하거나 복사하지 않고, 원본 폴더 전체를 백업·해시 수집하지 않는다.

## 꼭 필요한 자동 검증

기존 테스트 도구 또는 기본 런타임의 테스트 기능으로 다음 세 사례만 우선 확인한다. 이 준비 작업에서는 테스트 코드를 만들거나 실행하지 않는다. 실제 검토에서도 제품 코드는 변경하지 않고, 검증이 없으면 구현 담당에게 보완을 요청한다.

- **A1 저장·복원:** 임시 디렉터리에 한글·줄바꿈이 포함된 코드와 메모를 함께 저장하고 저장기를 새로 생성하거나 새 프로세스에서 읽어 두 문자열의 완전 일치를 검증한다. 두 번째 저장과 빈 메모도 포함해 예전 값으로 되돌아가지 않는지 확인한다.
- **A2 쓰기 실패:** 정상 기록을 만든 후 쓰기 오류를 유발해 실패가 호출자에게 전달되는지, 기존 파일이 유효하며 그대로인지 검증한다. UI의 편집 내용 유지·오류 표시는 M4에서 확인한다.
- **A3 손상 읽기:** 구문 오류와 잘못된 필드 구조 각각에 대해 명시적인 실패 결과와 손상 데이터 보존을 검증한다. 파일이 없는 최초 실행은 손상과 구별해 정상 샘플 로딩 대상으로 확인한다.

모든 자동 검증은 격리된 임시 경로에서 실행한다. 광범위한 E2E 체계나 스냅샷·커버리지 목표를 추가하지 않는다. 자동 저장 계층 검증이 실제 UI와 앱 종료·재실행 확인을 대신하지 않는다.

## 구현 후 받아야 할 증거와 최종 판정

- 대상 커밋과 실제 사용한 설치·실행·테스트 명령, 환경, 종료 코드 및 핵심 출력.
- 실제 UI 화면, 저장 성공 화면, 완전 종료·재실행 후 코드와 메모가 함께 복원된 화면 및 실행 기록.
- 사용한 저장 경로와 시험 데이터, 실패 주입 방법·오류 화면·편집값 유지 및 재시도 결과.
- 손상 파일의 재현 내용, 오류 표시, 보존 위치와 전후 비교 결과.
- 원본 보존 확인 범위·해시·비교 시점, 변경 파일 목록, 작업공간·버전별 경로 확인 결과.

구현 담당 증거를 받은 뒤 검토 담당이 M1~M7과 A1~A3의 실제 결과를 독립 보고한다. 실패에는 재현 절차와 기대값·관찰값을 붙이고, 환경 제약이나 미실행 항목을 숨기지 않는다. 필수 저장·복원·실패 처리 또는 실제 UI 확인이 남으면 완료 판정을 보류한다. 최종 보고에는 변경 내용, 실행 방법, 검증 결과, 남은 문제를 포함한다.
