## 사용 방법과 저장 단위

문제를 선택하고 **아이디어 열기 → 아이디어 추가**를 누른다. 빈 아이디어가 즉시 저장·선택된다. 목록에서 하나를 골라 본문을 편집하고 **저장 / Ctrl+S**를 누른다. 패널을 열어도 기존 코드·자유 메모 초안은 유지한다.

저장 단위는 **현재 문제의 코드·자유 메모·선택 아이디어 본문 전체**다. 다른 아이디어나 다른 문제는 바꾸지 않는다. 목록 이름은 첫 줄의 앞뒤 공백을 제거한 최대 60글자이며 비어 있으면 `새 아이디어`다. 같은 첫 줄·빈 본문을 여러 개 허용하며 UUID로 구별한다. 번호는 표시용이다.

문제/아이디어 선택, 문제/아이디어 추가, 패널 닫기에서 미저장 내용이 있으면 **계속 편집 / 버리고 이동 / 저장 후 이동**을 안내한다. 패널 닫기에서는 `버리고 닫기 / 저장 후 닫기`다. 저장과 버리기 모두 세 초안 전체에 적용된다고 대화상자와 화면에 표시한다. 취소/Esc는 세 값·선택·패널을 유지한다. 추가 실패 시에는 버리기를 먼저 선택했어도 기존 초안을 유지한다. 실패 후 같은 저장 버튼으로 재시도한다.

저장·추가 중에는 세 편집란을 읽기 전용으로 하고 목록·추가·패널 전환·중복 저장을 잠근다. 앱 종료의 기존 확인에 아이디어를 포함한다. 재실행 시 첫 문제, 닫힌 패널로 시작하며 패널을 열면 첫 아이디어를 선택한다. 마지막 선택과 패널 상태는 저장하지 않는다.

## 자료 형식과 이전

`study-record.json`의 schemaVersion은 3이다. 기존 문제 목록 각 항목에 `ideas: [{id, body, savedAt}]`를 추가했다. 기존 문제 ID는 그대로이며 새 문제/아이디어 ID는 main에서 UUID v4를 만든다. 아이디어 ID는 전체 파일에서 유일하고 저장 요청의 문제 소속인지 확인한다. renderer에는 `load`, `save`, `create`, `createIdea` 네 가지 제한된 API만 공개한다.

- 문제의 `savedAt`은 코드·메모 시각, 아이디어의 `savedAt`은 본문 시각이며 새 빈 항목은 `null`이다.
- 아이디어 추가·아이디어 본문만 저장할 때 코드·메모 시각을 바꾸지 않는다. 기존 `null`도 유지한다. 코드·메모가 변경되거나 아이디어 선택 없이 미저장 문제를 처음 저장하면 문제 시각을 갱신한다. 아이디어 본문 변경 또는 첫 저장 때 아이디어 시각을 갱신한다.
- v1/v2 읽기는 메모리에서만 v3로 해석하며 파일을 쓰지 않는다. 기존 코드·메모·시각을 유지하고 v2의 모든 ID·제목을 그대로 이어받는다. 새 아이디어 목록은 비어 있다.
- 첫 저장/추가 때 v1 원래 바이트는 `study-record.v1.json`, v2는 `study-record.v2.json`에 별도로 보존·동기화한 뒤 기본 파일을 교체한다. 기존 v1 사본은 v2 이전으로 바뀌지 않는다. 동일 바이트 사본은 재사용하며 다른 바이트면 덮어쓰지 않고 실패한다.
- 임시 파일 `0600`·파일 동기화·원자 교체·디렉터리 동기화·한 세대 `.bak`·외부 바이트 변경 감지를 유지했다. 손상/미지원 구조는 저장을 차단한다.
- 전체 8 MiB, 최대 1,000문제, 문제별 100아이디어, 코드 1,048,576/메모와 아이디어 본문 각각 262,144 UTF-16 단위다. 읽기와 쓰기에서 ID·자료형·시각·개수·크기를 검증한다.

원자 교체 뒤 디렉터리 동기화가 실패하면 완료를 확정할 수 없으므로 실패와 새 목록을 반환한다. 특히 아이디어 추가는 반환된 `ideaId`를 기억하고 **추가 확인 재시도**로 같은 항목을 다시 확인한다. 재시도 전에 전체 초안을 저장해도 최초 ID를 유지하며, 뒤의 재확인 쓰기가 다시 실패하면 진행 중 액션의 문제/아이디어 ID를 복원한다. 첫 줄/빈 본문을 재시도 키로 쓰지 않는다. 재확인 액션과 별개의 저장이 완료되거나 새 프로세스로 실행하면 일반 추가로 돌아가므로 의도적으로 별개 빈 아이디어를 만들 수 있다.

## 남은 문제와 미확인 범위

- 이 환경은 기존 sandbox 실행 제한이 있어 Playwright 기본값인 `--no-sandbox`에서 검증했다. OS sandbox 활성, 직접 한글 IME 입력, 네이티브 종료 대화상자 수동 클릭은 확인하지 않았다. 앱의 context isolation·Node 접근 차단·제한된 preload는 유지한다.
- 동기화 실패는 주입한 오류이며 실제 전원 차단·하드웨어 고장·외부 프로그램과의 모든 쓰기 경쟁을 입증하지 않는다. `.bak`은 전체 이력이 아니고 v1/v2 사본 이후의 기록을 포함하지 않는다.
- 사용자 실제 앱 데이터와 원본 학습 폴더, 인증 파일을 읽거나 수정하지 않았다. 검증은 합성 기록과 테스트 프로세스에 한정한다.
- GitHub CI는 PR 생성 후 실제 run/check 결과를 PR에 기록한다. #4의 임시 예외가 있어도 로컬 성공을 GitHub CI 성공으로 간주하지 않으며 재실행·계정/결제·보호 설정 변경을 하지 않는다.
- 독립 검토, 필요한 후속 수정, 정상 PR 병합, Issue/보드 완료 처리가 남는다. main 직접 푸시·PR 병합·Issue 종료는 구현자가 수행하지 않는다.

## PR #8 독립 검토 P2 후속 수정

[검토 댓글](https://github.com/dheorb/algorithm-study-desk/pull/8#issuecomment-6908681985)의 대상은 `2a6ce7f032fe5c2d953910ca590ad22122afd00d`다. 최초 22개 통합 테스트에는 **전체 저장 성공 뒤 재확인 쓰기가 한 번 더 실패하는 경계**가 빠져 있었다. `persist()`가 성공하면 재시도 Map을 지우는데, 이후 재확인이 교체 전에 실패하면 응답에 ID가 없어 다음 클릭이 새 A3 생성으로 바뀌었다.

제품 수정은 `executeAction()`의 실패 처리에서 진행 중인 `action.problemId`/`action.retryIdeaId` 쌍을 복원하는 세 줄(설명 두 줄 포함)이다. 재확인이 실패하면 같은 A2를 다시 시도하고, 성공 시 기존대로 재시도 상태를 해제한다. 별도로 저장을 완료한 뒤 명시적으로 새 항목을 추가하는 정책과 다른 문제의 ID 구분은 유지한다. 저장 계층·데이터 형식·IPC·의존성은 바꾸지 않았다.

검토자의 원본 스크립트를 수정하지 않고 `/tmp/study-desk-fix-007-3rk9bvvf/retry-boundary.cjs`로 복사해 root만 구현 작업공간으로 바꿨다. fixture와 캡처도 이 별도 임시 폴더에 생성했다.

- 수정 전: 검토 재현 사본 종료 1, `3 !== 2`; 새 저장소 회귀 테스트도 버튼이 `추가 확인 재시도` 대신 `아이디어 추가`가 되어 실패했다.
- 수정 후: 같은 재현 사본 종료 0, 두 번째 실패 뒤 재시도 버튼 유지, 다음 클릭에서 원래 A2 ID 선택과 항목 수 2개를 확인했다.
