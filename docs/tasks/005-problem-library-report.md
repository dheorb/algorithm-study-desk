## 결과와 선택한 동작

- 문제 목록, 현재 제목·선택 표시, 새 제목 입력과 실제 추가 경로를 제공한다. 추가 성공 시 빈 코드·메모의 새 항목을 저장하고 선택한다.
- 기존 데이터분석 ID는 `data-analysis`, 새 항목은 main에서 발급한 UUID v4다. 저장은 `{id, code, notes}`의 해당 항목에만 적용하며 다른 항목의 시각도 바꾸지 않는다.
- 제목의 앞뒤 공백을 제거하고 완전히 같은 제목은 거부한다. 빈 값·제어문자·120 UTF-16 단위 초과를 거부하며 HTML 모양도 `textContent`로 표시한다. 검색·삭제·이름 변경은 추가하지 않았다.
- 미저장 선택·추가에 계속 편집(Esc 포함), 버리고 이동, 저장 후 이동을 제공한다. 추가 실패는 버리고 이동을 골랐어도 기존 초안을 유지한다. 저장 후 이동의 저장이 실패하면 선택을 유지한다.
- 요청 중 편집은 읽기 전용, 선택·추가·저장 버튼은 비활성이다. Ctrl+S와 이벤트 처리에도 진행 중 검사를 적용한다. 저장 시작 시 ID와 내용을 복사한 뒤 파일 I/O를 시작한다. 저장 완료 후 새 편집이 가능하다.
- 전체 목록을 같은 `study-record.json`의 v2로 저장한다. 선택은 메모리 상태이며 선택만으로 파일을 쓰지 않고, 재실행 시 첫 항목을 연다. preload는 `load`, `save`, `create`만 공개하고 기존 Electron 보안 설정을 유지한다.

## v1 이전과 보호

v1을 읽을 때 파일을 변경하지 않고 메모리에서 데이터분석 항목으로 해석한다. 코드·메모·저장 시각 문자열을 그대로 이어받는다. 첫 쓰기 전에 원래 바이트를 `study-record.v1.json`으로 별도 보존·동기화하며 이후 일반 `.bak` 순환 백업으로 이 사본을 교체하지 않는다. 완성한 임시 파일의 hard link를 배타적으로 생성하므로 기존 복구 파일을 덮어쓰거나 반쯤 쓴 사본을 게시하지 않는다. 같은 사본은 재사용하고 다른 사본과 충돌하면 중단한다.

이전·저장 전에 원본 바이트 변경 여부를 검사한다. 쓰기는 임시 파일 동기화 → 복구/이전 저장본 확보 → 원자 교체 → 디렉터리 동기화 순서다. 교체 전 실패는 기존 기록과 메모리 목록을 유지한다. 교체 후 동기화 실패는 디스크에 반영되었을 수 있음을 실패로 알리고, 추가된 항목을 목록에 표시해 숨기거나 재시도 중복 생성하지 않는다. 기존 편집·선택은 유지한다.

문제 수 1,000개, 코드 1,048,576 / 메모 262,144 UTF-16 단위, 전체 직렬화 파일 8 MiB를 제한한다. 잘못된 UTF-8, 손상 JSON, 미지원 버전, 잘못된/중복 ID와 제목, 필드 타입·시각 오류를 자동 초기화하지 않는다. 실제 사용자 기본 데이터나 원본 학습 폴더에는 접근하지 않았다.

## 실행·검증

환경: Ubuntu 26.04.1 LTS, Node 22.22.1, npm 9.2.0, Electron 45.3.2, Playwright 1.65.1, 일반 사용자. 의존성·테스트 체계는 추가하지 않았다.

```bash
npm ci
npm test
xvfb-run -a npm run test:e2e
git diff --check
```

- 저장 계층: 12개 통과, 실패·건너뜀 없음.
- 실제 Electron 통합: 9개 통과, 실패·건너뜀 없음.
- 중간 통합 시도에서 지연 테스트 도우미의 dynamic import가 Playwright 평가 환경에서 실패했다. 제품에 우회 API를 넣지 않고 CJS 테스트 접근으로 수정한 후 해당 시험 및 전체 통합 검증을 통과했다.
- 권한 실패는 실제 `chmod 500`으로 재현하고 `700`으로 복구한다. 지연 및 특정 I/O 오류는 테스트에서 기존 store 메서드/파일 연산에만 주입한다. 미저장 전환 창은 실제 HTML dialog를 조작하며, OS 종료 dialog는 반환값을 '돌아가기'로 대체한다.
- 모든 기록은 직접 만든 fixture와 `/tmp/study-desk-unit-*`, `/tmp/study-desk-e2e-*`만 사용한다. 테스트 후 임시 기록을 제거한다. 캡처는 Git에 넣지 않고 `test-results/`에서 재생성한다.

직접 확인한 캡처 파일명: `library-restored.png`, `unsaved-choice.png`, `save-failure.png`, `saving-snapshot.png`, `v1-migrated.png`, `corrupt-library.png`, `narrow-title.png`. 화면의 목록·선택·본문 일치, 오류와 초안 보존, 저장 중 잠금, 740px 창의 가로 넘침 없음을 확인했다.

## 남은 제한

현재 호스트의 OS sandbox 실행 제한을 해결하지 않았으며 통합 검증은 Playwright의 기본 OS sandbox 비활성 설정이다. renderer Node 차단·context isolation·제한된 API 설정은 검사했지만 OS sandbox 활성 동작, 직접 한글 IME 입력, 네이티브 종료 창 수동 클릭, 실제 전원 차단·하드웨어 고장·동시 외부 프로그램 쓰기는 확인하지 않았다. 자동 저장·변경 이력 전체 복원은 제공하지 않는다.

#4 CI 임시 예외·보호 설정·workflow를 변경하지 않았다. GitHub에서 실행되지 못한 검사를 통과로 보고하지 않으며 최종 CI 상태는 PR 제출 후 조회해 PR에 남긴다. main 직접 푸시·PR 병합·Issue 종료·계정/결제/시스템 변경은 수행하지 않는다.
